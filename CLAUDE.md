# CLAUDE.md — rules for agents working in nadel-platform

Nadel is a SaaS for payment accounting in dacha (garden) cooperatives: a plot map colored by debt status,
tariffs, meter readings, a charges ledger, payment allocation, invoices delivered by email/Telegram/Viber,
a web account and mobile apps. Many cooperatives (tenants) share the platform and their data never overlaps.

Before starting any feature, read `docs/domain/money-rules.md`, `docs/domain/glossary.md`,
the feature spec in `docs/features/`, and the ADRs in `docs/adr/` if you are changing architecture.

## Layout

| Path | What it is |
|---|---|
| `api/openapi.yaml` | Single API contract. Source of truth for the server and all clients |
| `backend/` | Java 25, Spring Boot 4.1, Spring Modulith, Maven (wrapper: `./mvnw`) |
| `web/` | React + Vite + TypeScript + Tailwind. Member account and admin screens, by role |
| `mobile/` | Expo (React Native) for iOS and Android |
| `packages/api-client` | TS client generated by orval from `api/openapi.yaml`. Never edit by hand |
| `packages/shared` | Shared TS code: money, dates, plot statuses, i18n |
| `packages/ui-tokens` | Design tokens (colors, spacing, fonts) for web and mobile |
| `infra/` | docker-compose for local development, Keycloak realm, DB init scripts |
| `docs/` | ADRs, domain rules, feature specs |

## Commands

```bash
# infrastructure (Postgres + PostGIS, Keycloak)
docker compose -f infra/docker-compose.yml up -d

# backend
cd backend && ./mvnw spring-boot:run     # http://localhost:8080
cd backend && ./mvnw verify              # tests, including Testcontainers and module verification

# clients (from the repo root)
pnpm install
pnpm gen:api                             # regenerate packages/api-client from openapi.yaml
pnpm --filter web dev                    # http://localhost:5173
pnpm --filter mobile start               # Expo
pnpm -r typecheck && pnpm -r lint
```

Keycloak test users (realm `nadel`, password `nadel` for all):
`chairman@demo.local`, `treasurer@demo.local`, `electrician@demo.local`, `member@demo.local` belong to the Demo cooperative;
`member@other.local` belongs to another cooperative (for isolation checks); `operator@nadel.local` is the platform operator.

## Feature workflow (Definition of Done)

1. A spec exists in `docs/features/NNN-name.md` (template: `000-template.md`), with worked calculation examples if the feature touches money.
2. Change `api/openapi.yaml` first, then run `pnpm gen:api`. The server implements the generated interfaces.
3. The DB schema changes only through a new Flyway migration `backend/src/main/resources/db/migration/V{N}__name.sql`. Existing migrations are never edited.
4. Every new table with cooperative data has `tenant_id uuid not null`, RLS enabled, a `tenant_isolation` policy and an index on `tenant_id`. An isolation test is mandatory.
5. Backend: unit tests for domain logic plus an integration test on Testcontainers. `./mvnw verify` is green, including `ModularityTests`.
6. Clients: `pnpm -r typecheck` and `pnpm -r lint` are green. UI text goes only through i18n catalogs (`packages/shared/src/i18n`); Ukrainian is the default UI language.
7. Demo data is updated if the feature displays something.

## Hard rules (a violation means the review is rejected)

**Language**
- Everything in the repository is in English: code, comments, docs, commit messages, test names, SQL comments, demo data.
- The only exception is end-user UI translations inside `packages/shared/src/i18n` (Ukrainian catalog `uk.ts`).

**Money**
- Amounts are `BigDecimal` in Java, `numeric(14,2)` in the DB, and strings in JSON (`"1250.50"`). Never `double`/`float`/`number` for calculations.
- Only the server calculates money. Clients display amounts, debts and statuses but never compute them.
- The ledger (`charge`, `payment`, `allocation`) is append-only. No `UPDATE`/`DELETE` of ledger rows. Corrections are a reversal plus a new entry with a reason.
- Rounding happens in exactly one place, the `Money` value object (`RoundingMode.HALF_UP`, 2 decimal places).

**Multi-tenancy**
- The application connects to the DB as the `nadel_app` role, which has no `BYPASSRLS`. Migrations run as `nadel_owner`.
- The current cooperative is set at the start of every transaction (`app.tenant_id`), see `tenancy/internal/TenantAwareTransactionManager`. Do not bypass it: no data queries under `@Transactional(propagation = NOT_SUPPORTED)`, no native queries outside a transaction.
- `tenant_id` never comes from a request body or query parameter. Only from the token.
- The platform operator cannot see cooperative data.

**Modules (Spring Modulith)**
- Top-level packages under `app.nadel.*` are modules. A module talks to another only through its public API (the module's root package) or through domain events. `internal` subpackages are closed.
- A module never reads another module's tables directly.
- Cross-module side effects (notifications, recalculations) go through events and the outbox, not direct calls.

**Security and data**
- Roles: `CHAIRMAN`, `TREASURER`, `ELECTRICIAN`, `MEMBER`, `PLATFORM_OPERATOR`. Permissions are checked on the server with `@PreAuthorize` at service or controller level.
- Admin actions that change data are written to the audit log.
- Personal data is never logged (names, phone numbers, emails, addresses).
- Secrets come only from environment variables. The repository contains only dev values for the local docker-compose.

**General**
- Do not add a dependency without a reason. A new backend library gets a short note in the PR; an architectural one gets an ADR.
- Do not edit generated code (`packages/api-client/src/generated`, `backend/target/generated-sources`).
- Commit messages follow Conventional Commits (`feat(ledger): ...`, `fix(web): ...`).
- Commits must not mention AI: no `Co-Authored-By` lines for AI assistants, no session links, no "Generated with ..." lines. The commit author is the repository owner.
