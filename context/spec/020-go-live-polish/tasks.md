# Tasks: Ready for real use — inviting members, tariff fixes, small review items (020)

Rules for every slice: contract-first (`api/openapi.yaml`, then `pnpm gen:api`; never edit generated code); Flyway only,
new migrations never edit old ones; every new tenant table has `tenant_id`, RLS `tenant_isolation`, an index and an
isolation test; permissions via `@PreAuthorize("hasAuthority('PERM_…')")`; Problem Details with codes, no display text
from the server; every UI text through `packages/shared/src/i18n/{uk,en}.ts` (Ukrainian default, both catalogs); audit
for admin changes; no personal data, link or password in logs; exact dependency pins; no edits to `.github/`,
`CLAUDE.md`, `.claude/` or `.mcp.json` (propose them in the report instead); Conventional Commits, no AI attribution.
"TC x.y" = sections of `technical-considerations.md`; "FS x.y" = sections of `functional-spec.md`.

**Testing in this run (the user's instruction):** no tests are run until every implementation slice is done. Builders
write the tests listed in their task (unit, integration, e2e) but do **not** run `./mvnw test/verify`, `vitest`,
`playwright` or `make check`; they may run a compile (`cd backend && ./mvnw -q -DskipTests compile test-compile`) or
`pnpm -r typecheck` only to finish their own code. There is no per-slice Verify task. The whole feature is verified
once, in the last slice and in the pipeline's Phase 4. Help screenshots are taken in the last slice (they need the
running app).
