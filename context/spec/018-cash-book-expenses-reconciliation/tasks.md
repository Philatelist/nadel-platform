# Tasks: Cash book, expenses and reconciliation (018)

Rules for every slice: contract first (`api/openapi.yaml`, tag `treasury`; the two PDFs under tag `documents`; then
`make gen`); schema only through new Flyway migrations — `V32__treasury.sql` (written in Slice 1 with every 018 table,
guards, grants, permissions, `seed_treasury` and the payment backfill); a later slice adds V33+ only if needed and never
edits an applied migration; every new cooperative table has `tenant_id`, RLS, `tenant_isolation`, a tenant index and an
isolation test; money only as `Money`/`BigDecimal`, `numeric(14,2)`, strings in JSON; the client never computes amounts;
`account_movement`, `expense`, `expense_attachment`, `handover`, `other_income` are append-only (trigger + grant tests);
counterparty and descriptions sealed through `PersonalDataCipher` (never in plaintext in tables, logs, audit or outbox);
permissions `CASHBOOK_VIEW`/`CASHBOOK_ENTER`/`CASHBOOK_APPROVE`, never role names; every screen text through the i18n
catalogs (uk default, both catalogs); PDFs in Ukrainian from the documents bundle (ADR 0012); Problem Details with a
`code`; audit through `AuditEvent` in the changing transaction; no new backend library (JDK-only attachment parsing);
no new client dependency (HEIC via the browser's own decoder); no edits to generated code, `.github/`,
`CLAUDE.md` or `.claude/`; Conventional Commits, no AI attribution in commits. Builders run only the slice's Verify
command and the tests of the classes they changed — never the full backend suite (`./mvnw verify`, `make test`,
`make check`); the full suite runs once in Phase 4. Every Verify task stops anything it started and deletes its own
temporary files. References "TC x.y" are sections of `technical-considerations.md`; "FS x.y" of `functional-spec.md`.
