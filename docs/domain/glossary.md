# Glossary

| Term | Code | Meaning |
|---|---|---|
| Cooperative | `Tenant` | A platform customer. All data belongs to exactly one cooperative |
| Plot | `Plot` | A land plot with a number, area and polygon on the map. Kind: plot or common land |
| Sotka | — | 100 m². Plot area is stored in m² and shown in sotkas in the UI |
| Member | `Member` | A natural person in a cooperative's member list. May own several plots. Signs in when their Keycloak account is linked to the member record. Archived, never deleted |
| Ownership | `Ownership` | Member–plot link with a share and a validity period (`validFrom`, inclusive `validTo`, empty while current). The current owners of a plot (not common land) have shares that add up to exactly one whole, or the plot has no owner. A member may own several plots; the same member never owns a plot in two overlapping periods. Rows are never deleted: a past owner stays in the history (feature 007) |
| Share | `Share` | An exact fraction `n/d` of a plot owned by one owner (`1/2`, `2/3`, default `1/1`; shown in lowest terms, so `2/4` becomes `1/2`; `d` is at most 1000). Never a decimal. Money-bearing features split by shares only through this type |
| Change of owner | `OwnershipCommands.change` | One operation on a plot from a date: every current owner's period ends the day before, the new owners start on that date, with an optional basis (sale contract, inheritance, court decision). An empty list leaves the plot without an owner. The date is not in the future and later than every current start and past end. One audit entry `OWNERSHIP_CHANGED` per change |
| Correction | `OwnershipCommands.correct` | Fixes a mistake in one ownership record (member, share, dates, basis) and, in the same step, the shares of its co-owners, with a required reason. The old values stay in the audit log (`OWNERSHIP_CORRECTED`); records are corrected, never erased |
| Plot status visibility | `memberPlotStatusVisibility` | Cooperative setting (`settings` module, `SETTINGS_MANAGE`): `OWN_ONLY` (default) shows a member the status colour only of plots they own, `ALL_PLOTS` shows every plot's colour to every member. Amounts, owners and personal data of other plots are never shown to a member; people with `PLOTS_VIEW` always see every colour |
| Import | `ImportRun` | Loading plots, members and current ownership from one `.xlsx` file (sheets Plots, Members, Ownership) by the chairman (`IMPORT_RUN`). Two steps: a preview, then a commit in one transaction. Plots are matched by number, members by e-mail or by last name + first name + first phone; ownership already recorded is skipped, different ownership is an error. Re-importing the same file changes nothing. The file never archives or deletes records. Each upload is kept in the import history (feature 008) |
| Preview | `ImportPreview` | The result of checking an uploaded file without saving anything: counts of new, updated and unchanged records per sheet and the problems by sheet, row and column. It can be committed for 30 minutes, only when it has no problems and changes something, and only while the data it was based on has not changed (otherwise `IMPORT_STALE`) |
| Charge type | `ChargeType` | What the cooperative charges for: a seeded type (membership fee, electricity, land tax, water and, since feature 011, common consumers; all active except water, which stays inactive until the cooperative switches it on) or a custom one such as a special-purpose fee. Has a name unique among non-archived types (ignoring letter case), a description, an active flag and a position. A seeded type shows a localised default name until it is renamed (`nameCustomized`). An archived type is hidden from the list, its name is freed, nothing about it changes any more, and its tariffs never apply; an inactive type stays in the list but gives no expected amount (feature 009) |
| Tariff | `Tariff` | The calculation rule for one charge type: a name, versions and a scope. A charge type may have several tariffs. A tariff is created together with its first version and applies to all plots until its scope is changed; it is never renamed or deleted (feature 009) |
| Tariff version | `TariffVersion` | Rate, basis, frequency and, for a one-time fee, a due date, effective from `validFrom`. A change of rate is a new version, and two versions of a tariff never start on the same date; a version can be corrected or deleted until a charge uses it, and after that a correction goes through recalculation (feature 012). A version applies until the day before the next one starts; that end date is derived on every read, never stored |
| Rate | `Rate` | The number in a tariff version, for example `4.3200` UAH per kWh. Not negative, at most four decimals, never rounded (a fifth decimal is rejected) and not money: it becomes an amount only through `Money.ofQuotient` in the calculation (ADR 0013) |
| Basis | `Basis` | What a rate applies to: `PER_PLOT`, `PER_AREA_SOTKA` (per sotka of the plot's area), `PER_KWH`, `PER_M3` (both depend on meter readings) or `FIXED_ONE_TIME` (a fixed amount, due once) |
| Frequency | `Frequency` | The period a rate is meant for: `MONTHLY`, `QUARTERLY`, `YEARLY`, or `ONE_OFF` (only with `FIXED_ONE_TIME`, which needs a due date) |
| Tariff scope | `TariffScope` | Which plots a tariff applies to: `ALL_PLOTS` (the default; common land is never included) or `SELECTED_PLOTS`, a list of chosen plots. Replaced as a whole by one change, which is audited |
| Exclusion | `TariffScopePlot` (kind `EXCLUDED`) | A plot of an `ALL_PLOTS` tariff that the tariff does not apply to, with a required reason (up to 500 characters). The expected amount shows it as excluded, with the reason, and not as zero |
| Expected amount | `ExpectedCharge` | What a plot would be charged by its tariffs in a month, calculated on the server by `ChargeCalculator` from the versions valid in that month and the plot area: the days of each version over the days of the month, summed, rounded once. A one-time fee counts only in its due month. A `PER_KWH` or `PER_M3` tariff has no amount ("by readings"). A preview; the month run of feature 011 charges the same amount. A member sees it only for plots they own |
| Meter | `Meter` | A meter of a plot (electricity or water) or of the network (substation, quarter, common consumer). A plot has zero or one active meter per resource; a replaced meter keeps its history (money-rules 6.1–6.3) |
| Meter reading | `MeterReading` | A meter's value on a date (`MeterValue`: at most three decimals, not money). Source: `ENTERED` (board or electrician), `IMPORTED` (Excel), `MEMBER` (a plot owner). Status: `PENDING` (member, waits for approval), `APPROVED` (counts), `REJECTED` (with a reason), `SUPERSEDED` (replaced by a later entry for the same date or a correction, kept in the history). Money-rules 6.4 |
| Interval consumption | — | The difference between a reading and the previous point of the same meter |
| Range consumption | `RangeConsumption` | `value(to) − value(from)` clipped to the meter's working period and summed over the plot's chain of meters; a value between two readings is interpolated and marked calculated; unknown when a value cannot be determined (money-rules 6.4). A run of feature 011 counts the days `from..to` with end-of-day values, `value(to) − value(from − 1)` |
| Transformer losses | — | A node meter's consumption minus the consumption of the meters under it. Charged to plots as a fixed percentage of every electricity interval (`FIXED_PERCENT`) or by losses runs (`PROPORTIONAL`), as the cooperative chose (money-rules 6, 6.6) |
| Substation meter | `Meter` (kind `SUBSTATION`) | Meter at the cooperative's transformer; root of the meter tree |
| Quarter meter | `Meter` (kind `QUARTER`) | Intermediate meter for a group of plots (a street or block); its losses are shared among those plots |
| Common consumer meter | `Meter` (kind `COMMON_CONSUMER`) | Meter of a shared consumer such as a well pump or street lighting |
| Water meter | `Meter` (resource `WATER`) | Water meter of a plot, readings in m³. Charged per m³ once the "Вода" charge type is active and has a per-m³ tariff, only for the days the plot is connected to water |
| Water connection | `plot_water_connection` | A plot connected to a water source (a well's pump meter, or the cooperative's water supply) from a date and, once disconnected, until a date; the history is kept, at most one lasting connection. Water tariffs charge only connected days; a well pump is shared among its connected plots (money-rules 11) |
| Plot-days | — | The number of days each plot was connected to a water source in a run's range, added over the plots: the base of the `CONNECTED_PLOTS` split of a well pump |
| Billing month | `billing_month` | The accounting period of the ledger, "Відкритий" (open) or "Закритий" (closed). Months close in order and are never reopened; a charge about a day of a closed month is booked in the earliest open month, keeping its own service period (money-rules 3.1) |
| Charge | `Charge` | Ledger entry of a plot and a charge type: amount, kind, source, the billing month it is booked in, the service period, the debt date, the author and how it was calculated. Never changed or deleted (money-rules 3) |
| Charge kind | `ChargeKind` | `REGULAR` (an accrual), `REVERSAL`, `OPENING` (an opening balance) |
| Charge source | `ChargeSource` | What produced a charge: `TARIFF` (the month run), `CONSUMPTION` (a meter interval), `LOSSES`, `COMMON_CONSUMER`, `OPENING`, `MANUAL_REVERSAL` |
| Service period | `serviceFrom`, `serviceTo` | The days a charge pays for ("за 13.09–28.09"); may lie in an earlier, closed month than the one it is booked in |
| Debt date | `accruedOn` | The day a charge's debt counts from for the plot status: the first day of the month (month run; a one-time fee: its due date), the reading date, the last day of a run's range, an opening balance's date |
| Reversal | `Charge.kind = REVERSAL` | Entry that cancels one earlier charge: the opposite amount, a mandatory reason, the original named. A charge is reversed at most once, a reversal never; a charge of a closed month is corrected by an adjustment (feature 012) instead |
| Opening balance | `Charge.kind = OPENING` | A plot's debt per charge type as of the go-live date, entered by hand or by the "Вхідне сальдо" / "Opening balances" import sheet; positive, dated not in the future (money-rules 3.2) |
| Month run | `MonthRun` | "Нарахувати місяць": charges every chargeable plot every recurring or one-off tariff that applies in a billing month, after a preview; a rerun charges only what is missing; conflicting tariffs go to the "not charged" queue (money-rules 4.1) |
| Losses run | `losses_run` | "Розрахунок втрат" for a range of days in the `PROPORTIONAL` mode: the losses of every node of the meter tree shared among the plots under it by consumption; negative and unknown nodes are skipped with a warning; reversed as a whole (money-rules 6.6) |
| Common consumer run | `common_consumer_run` | "Спільні споживачі" for a range of days: each common consumer's consumption split among plots (connected plots by plot-days, equally per plot, service users, or not charged) and charged at the "Спільні споживачі" tariff; reversed as a whole (money-rules 6.7) |
| Not charged item | `not_charged_item` | "Не нараховано": a case the app could not charge, with its reason (no tariff for every day, conflicting tariffs, outside scope, excluded, unknown node or consumer value) and a link to fix it; retried by "Повторити" and by the next month run (money-rules 3.3) |
| Plot account | `PlotAccount` | "Рахунок" on the plot card and "Мої нарахування" for a member: the charges of a plot with their calculation and the debt per charge type |
| In use | `TariffVersionUsage`, `ReadingUsage` | A tariff version or reading that a charge or run (not reversed) was calculated from; it can no longer be corrected or deleted until the recalculation of feature 012 |
| Red threshold | `redAmount`, `redDays` | "Поріг червоного статусу" in the settings: a debt above the amount (default 1 000,00) or older than the days (default 90) makes a plot red |
| Payment | `Payment` | Money received: from a bank statement or as cash through the cash desk |
| Receipt | `Payment.receiptNumber` | Sequential per-cooperative number of a cash payment, shown to the member |
| Allocation | `Allocation` | Link of part of a payment to a specific charge |
| Prepayment | — | Unallocated remainder of a plot's payments |
| Invoice | `Invoice` | Monthly document with the amount due, bank details and an NBU payment QR code |
| Plot status | `PlotStatus` | Map color from the plot's debt: RED (above the red threshold, by amount or age), YELLOW (any other debt), GREEN (no debt), GREY (common land or no owner). Derived when read from the cached debt (money-rules 9) |
| Treasurer | `TREASURER` | Base role. Admin who allocates payments; starts with the view permissions: members, plots, audit log, tariffs, meters and charges |
| Chairman | `CHAIRMAN` | Base role. Head admin of the cooperative; always has every permission. A cooperative keeps at least one active chairman |
| Member role | `MEMBER` | Base role every ordinary member holds; no permissions by default, sees only their own data |
| Electrician | — | Admin who works only with meters. Not a base role: a custom role. In the demo cooperative the role "Електрик" (member `electrician@demo.local`) is granted `METERS_VIEW` and `READINGS_ENTER`: it sees the meters and the reading round and enters readings, but cannot register, replace or remove a meter or approve a member's reading |
| Platform operator | `PLATFORM_OPERATOR` | Owner of the SaaS. Manages cooperatives and subscriptions, cannot see their data |
| Permission | `Permission` | A single allowed action from a fixed list, for example `PAYMENTS_ALLOCATE` or `MEMBERS_EDIT` |
| Role | `Role` | A named set of permissions stored per cooperative. Base roles (Chairman, Treasurer, Member) exist in every cooperative and cannot be deleted, but can be renamed (feature 004; the code stays, `Role.nameCustomized` tells a renamed role from one that still has its standard name); custom roles are added by anyone with `ROLES_MANAGE`. A member may hold several roles (table `member_role`) and gets the union of their permissions |
| Audit entry | `AuditEvent` (table `audit_entry`) | Append-only record of an admin change: who, when, what, and old and new value of each changed field |
